# 70 — 医疗安全规则（不可协商）

## 产品医疗边界

本工具**禁止**提供任何会构成以下行为的功能或文案：

1. 自动诊断疾病或听力状况（含"你可能患有……"式表述）。
2. 处方建议：推荐用药、停药、修改药物剂量。
3. 人工耳蜗 programming / 设备调机的具体医疗参数。
4. 替代医生或听力师的专业判断。
5. 保证或暗示训练必然产生临床疗效（"坚持训练即可恢复听力"类话术一律禁止）。
6. 把工程指标当临床指标：ASR>85%、音素评分、≥80% 正确率升降级阈值均为**待验证的工程目标/产品规则**，不得表述为医学规律或临床标准。

## 安全架构要求（SAFE-* 任务的验收基线）

- **Risk Taxonomy**：风险分类清单（诊断类/用药类/调机类/急症类/心理危机类/一般健康教育类），版本化管理。
- **Query Classifier**：用户输入先分类再路由；高风险类 → 拒答 + 转诊话术，不进入 LLM 自由生成。
- **Safety Policy**：统一策略模块（复用/扩展 `app/core/safety.py`），禁止多处独立维护关键词表（历史 ARCH-04 教训）。
- **Unsafe Answer Blocker**：LLM 输出发送前拦截；流式场景必须缓冲后检查再放行（历史 S4 教训），输入检查覆盖最近多条消息（历史 S5 教训）。
- **Emergency Route**：急症/心理危机（如自杀倾向）→ 固定应急话术 + 建议立即联系医生/急救渠道；不走 LLM 生成。
- **High-risk Referral**：高风险但非急症 → 拒答模板 + 建议咨询听力师/耳鼻喉科。
- **Safety Event + Audit**：每次拦截/转诊落安全事件表（时间、类别、命中规则、处置），可审计、可统计。
- **Safety Eval**：固定医疗安全评测集（含诱导性提问、多轮绕过、历史消息注入），作为回归测试；任何触及对话/RAG/文案的任务，Machine Gate 必须跑医疗安全回归；无测试时不得以"没有测试"视为通过——记 skippedGates 并把补测试纳入 Scope。

## 文案规则

- 免责声明：产品入口与教育回答页须展示"本工具不提供医疗诊断与建议，请咨询您的听力师或医生"。
- 训练建议措辞：使用"建议练习/可能有助于"，禁止"治疗方案/临床处方/必然改善"。
- 数据展示：正确率、评分仅呈现为训练进展参考，禁止与"听力恢复程度"划等号。

## 用户特殊群体

- 老年/人工耳蜗用户可能存在构音差异：发音评分低不等于医学异常，反馈文案禁止病理化表述（如"发音障碍严重"），须使用建设性训练建议。
- 心理敏感场景（康复挫败感）：避免施压性文案，提供鼓励与人工求助入口。

## 违规处置

- Review/Verify 阶段发现诊断/处方/调机参数/疗效保证类输出 → 直接 blocker（REQUEST_CHANGES / TASK_FAIL），无警告缓冲。
- Release Gate 医学安全回归失败 → PROJECT_NOT_READY。
